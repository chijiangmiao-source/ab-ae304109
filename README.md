# 控制表达式代数重写复核

面向飞控规程评审场景：在替换控制表达式之前，确认候选式是否可由
**已批准的代数重写规则**推出，而不是靠若干输入样例猜测等价。

系统对两个受限表达式与至多 20 条等式规则执行**同余闭包 + 等式重写
饱和**，仅在闭包饱和后才判定等价/不等价；资源耗尽而未饱和时给出
“未完成”；输入非法时给出“无效”并清除旧结论。

## 受限输入

* 表达式仅含**具名常量**与**一元/二元函数调用**，例如
  `f(add(a,b), h(c))`；无运算符、无数值字面量。
* 叶子命名约定：**单个小写字母**（`x`、`y`……）为规则中的全称量化
  变量，其余标识符（`zero`、`nil`、`a0`……）为必须字面匹配的
  具名常量。
* 规则形如 `lhs = rhs`，至多 20 条；**右侧不得引入左侧未出现的
  变量**（具名常量不受此限），例如 `f(x)=g(y)` 会被拒绝。
* 形如 `g(x)=zero`（左式变量比右式多）的规则只正向应用，不做
  可能凭空捏造变量的反向重写；两侧变量集相同（如交换律、结合律）
  时双向应用。
* 任一推导项不得超过声明的 **80 个节点**（`max_nodes` 可在页面/
  接口调整，默认 80）；规则有效应用次数默认上限 5000。

## 四种结论

| status | 含义 | 证据/摘要 |
| --- | --- | --- |
| `equivalent` | 饱和后同属一个等价类 | 逐步规则实例（含替换、方向）与同余依据，同余可下钻其参数等价前提 |
| `not_equivalent` | 已饱和但分属不同等价类 | 稳定等价类摘要（固定代表元 + 成员 + 16 位 digest），**清除旧证据** |
| `unknown` | 触及节点/应用次数上限前未饱和 | 返回未完成，不作等价判断，不产出证据/等价类 |
| `invalid` | 语法错误、未绑定变量、规则/表达式超限 | 列出问题，**不携带任何旧结论** |

## 确定性

* 等价类代表元固定为**结构签名字典序最小**的成员；
* 同余表按签名保存全部成员并随合并实时迁移；
* 待合并队列与**待重建队列**均为 FIFO，处理顺序确定；
* 摘要、digest（FNV-1a-64）、规则枚举顺序与运行次数无关，
  左右式交换提交得到同一组等价类摘要。

app/engine/api.py        校验 + 饱和驱动 + 规范摘要/结论

## 本地运行（仅需 Python 3.11+，无第三方依赖）

```bash
# 启动页面与接口（端口可用 HOST_PORT 配置）
HOST_PORT=8080 python3 -m app.web.server

# 运行测试
python3 -m unittest discover -s tests -v

# 一次性验收：构建检查 + 三类场景 HTTP 冒烟 + 测试，退出码报告结果
./verify/verify
```

接口：

```bash
curl -s localhost:8080/api/verify -H 'Content-Type: application/json' -d '{
  "left": "f(add(a,b))",
  "right": "f(add(b,a))",
  "rules": ["add(x,y) = add(y,x)"],
  "max_nodes": 80
}'
```

## Docker Compose

宿主端口可配置（默认 8080）：

```bash
HOST_PORT=9090 docker compose up --build
# 页面 http://localhost:9090/   健康检查 /healthz
```

`verify` 是**执行后退出的一次性服务**，围绕交换律等价推导、饱和后
非等价、资源受限未完成三类场景对**真实运行的 web 服务**做 HTTP/
接口冒烟，期间穿插运行代码测试与构建检查，并以退出码报告结果：

```bash
# 构建后跑一次性验收（成功退出码 0）
docker compose run --build --rm verify

# 或一条命令：web 常驻，verify 结束即按其退出码收口
docker compose up --build --abort-on-container-exit --exit-code-from verify
```

## 关键判定语义

* **饱和才判定**：待合并队列、待重建队列清空，且一整轮双向规则
  扫描不再产生任何新项/新合并，才认为闭包饱和。
* **同余**：两个调用函数符号相同、各参数逐对等价则合并；其依据
  携带参数等价前提，可继续下钻到规则实例。
* **未完成**：规则实例节点数超过 `max_nodes`，或有效应用次数
  超过 `max_applications`，而此时闭包尚未饱和。
* **无状态请求**：每次复核从空闭包构建；无效、未完成都不会返回
  上一次请求的证据或等价类。
